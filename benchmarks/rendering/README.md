# Prospective rendering-engine measurements

This workload measures the actual local editor engine before introducing workers.
It is separate from the frozen NIST/authoring studies, user adoption, blind visual
quality and browser or application startup. No persistent worker is implemented
by this checkpoint. The full85–89 scope remains open.

## Reproduce

Use the scientific interpreter and working Node/Git runtime for the source
checkout, with its packaged translator already built:

```sh
python scripts/rendering-benchmark.py --out-dir /absolute/new-directory
python scripts/rendering-benchmark.py --smoke --out-dir /absolute/another-new-directory
```

The complete run has five cases, each one first request with a fresh owned font
cache, seven ordinary warm-font fresh subprocesses and one separately instrumented
warm request:45 records. The conformance smoke uses one ordinary warm repetition
and has15 records; it is not pooled into the formal baseline. Existing outputs
are never overwritten. Full raw artifacts, reports, native maps and per-run hashes
stay in the new directory; inspect results.json and actual images.

Ordinary controller time includes prepare, one local conversion, one native
subprocess and strict report/export/geometry binding. Upload is measured separately.
Artifact hashing, harness/browser/HTTP/application startup are excluded. Phase
instrumentation uses the same original generated bytes, native geometry/inspection
hooks and CLI policy, then requires matching source/spec/data/semantic report,
actual PNG RGBA/dimensions and table Markdown/TeX when applicable. Its nested-aware
exclusive times avoid double counting; inclusive costs overlap. Instrumented
requests never enter ordinary medians. There are no CI timing thresholds.

The first font-cache request and warm-font requests are distinct conditions.
Warming fonts in a fresh process is not persistent-worker reuse. OS/page caches
are uncontrolled; current small exploratory cases informed this workload, which
is developer-selected and not held out.

## Protocol and amendment

[protocol.json](protocol.json) pins original case bytes, expected strict outcomes,
schedule, measurements and worker-conformance requirements before this baseline.
The cases cover the public24-row demo, original complete long child/table inputs,
20000-row synthetic median/seed-bootstrap stress, and an original-data false claim
that must remain strict failed while preserving review exports.

The initial [v1 protocol](protocol-v1.json) accidentally included an empty optional
claims array in the dense case; the canonical compiler correctly refused it. The
first harness then reported KeyError:None while looking up an absent render.
All45 attempts, original cases and exact harness sources remain under
[history/](history/), with36 matching original cases and nine refused dense
translations. [The v2 amendment](history/amendment-v2.json) omits only the empty
optional property, retains the same20000 observations/median/bootstrap work and
all five cases/outcome gates, and records the diagnostic harness correction.
Line plots do support median aggregation; this was an input-shape mistake.
All five cases must be rerun; the failed v1 is never counted as accepted.

Any later case/gate/metric change needs a versioned amendment retaining the
original. Executor and instrumentation source hashes accompany every run. Future
worker comparisons must preserve startup/font conditions, all strict negatives,
namespace/input/run ownership, lifecycle/timeout/crash recovery and scientific
outputs. Faster throughput alone does not establish human productivity.


## Observed final baseline2026-10-30

[All45 actual outcomes](results/baseline-v2.json) meet their original expectations:
36 clean passed/exit0 and nine false-claim failed/exit2, with matching original
semantic reports/data/script/PNG pixels and table text. Four clean cases and one
negative each have seven primary warm repetitions; first-font and instrumented
requests remain separate. [Compiler runtime](results/compiler-runtime.json) is
queried separately after measurement. This source/native engine baseline does not
include a worker, browser/app startup or published PyPI feature release.

| Case | Ordinary warm-font engine median |
| --- | ---: |
| demo-bootstrap | 0.5753s |
| long-sparkline | 0.6508s |
| long-grouped-table | 0.5190s |
| dense-median-bootstrap | 1.4406s |
| false-comparison | 0.5762s |

The dense median/bootstrap phase takes substantial time in this workload, while
small cases expose module/process overhead. These observations motivate separate
worker and statistics-cache experiments. Their benefits remain unmeasured.

For a genuinely installed local wheel matching the checkout, select its Python
and use --installed. The runner rejects source imports in that mode and checks
six actual package asset bytes; a matching version string is insufficient. Public
0.8.0 predates the current source. CI runs the15-record smoke under Python3.10 and
3.12 and retains complete artifacts without enforcing any latency threshold.
